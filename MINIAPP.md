# Мэтч · Telegram Mini App

Основной интерфейс — адаптивное Mini App: знакомства со свайпами, взаимные мэтчи, мессенджер, анкета и настройки. Старые анкеты и переписки остаются в той же SQLite-базе. Бот остаётся точкой входа, каналом уведомлений и инструментом модератора.

## Дизайн

- **Тёмная слива:** фон `#120d1e`, поверхности `#1b142a`, акцент `#b49aff`.
- **Светлая лаванда:** фон `#f5f1fb`, поверхности `#fffaff`, акцент `#8159cb`.
- Тема выбирается автоматически по Telegram при первом открытии и меняется вручную; предпочтение хранится локально без персональных данных.
- Векторный логотип `dating/web/logo.svg`: буква «м», точка встречи и искра. Анимации запуска, реакции и мэтча; кнопки с тактильным откликом при поддержке Telegram.
- Свайпы используют пружинную модель с жесткостью 185 и затуханием 24, ограниченными шагами интегрирования. Учитываются расстояние и скорость жеста. Свайп не заменяет доступные кнопки.
- `prefers-reduced-motion` отключает пружинные и декоративные анимации. Разметка поддерживает узкий экран, тёмную тему, safe area и изменение высоты при открытии клавиатуры.
- Демо-портреты сгенерированы и относятся к вымышленным анкетам. Их нет в рабочей базе.

Скриншоты в `docs/screenshots/`: desktop-dark, desktop-light, mobile-dark, mobile-light, messenger-dark. Они показывают демонстрационный интерфейс, не опубликованный сервис.

## Данные и безопасность

`initDataUnsafe` не используется для авторизации. Сервер проверяет HMAC-подпись `Telegram.WebApp.initData`, срок действия (24 часа), отсутствие дубликатов параметров и корректный ID. Изменение переданного клиентом `user_id` не позволяет писать от другого участника.

Все `/api/*`, включая фотографии и поток обновлений, требуют подписанные данные через заголовок `X-Telegram-Init-Data`. Нет токена бота в JS, URL фотографии или запросах браузера. Авторизация и данные не передаются внешним аналитическим сервисам; CORS не открыт.

Вне Telegram интерфейс явно показывает **Демо**. Его адаптер работает только в памяти браузера и не отключает защиту настоящего API. Перезагрузка сбрасывает демо. На настоящем Telegram-входе ошибки авторизации не переключают пользователя в демо.

Фото передаются владельцем через API (JPG/PNG/WEBP до 5 МБ), проверяются по заголовку файла и отправляются владельцу ботом для получения Telegram file ID. Бот должен иметь разрешение писать пользователю. Затем фото выдаётся только через авторизованный серверный прокси без раскрытия Bot API URL. Telegram дополнительно проверяет файл; для проблемных форматов используйте JPG/PNG.

## Мессенджер

- Диалоги доступны только при действующем мэтче, активных анкетах и отсутствии личной/глобальной блокировки.
- Сообщения сохраняются в SQLite до ответа API. Клиентский nonce обеспечивает идемпотентную повторную отправку после неопределённого сетевого результата.
- В Mini App `sent` означает сохранение в доступной собеседнику истории. Галочка не утверждает, что пришло Telegram-уведомление. Двойная галочка появляется после открытия и просмотра конца диалога получателем.
- Живые обновления идут через авторизованный SSE-поток (`fetch`, без секрета в query string). Передаётся только сигнал обновления; содержимое загружается отдельным защищённым запросом.
- Резервный опрос раз в 4 секунды восстанавливает состояние при потере потока. Фоновое окно прекращает опрос; после возвращения обновления восстанавливаются.
- История загружается порциями по 40, сообщения упорядочены по ID, ответы экранируются. Текст до 2000 символов. Медиа, голосовые, typing-индикатор, редактирование/удаление отдельных сообщений и сквозное шифрование не реализованы.
- Блокировка закрывает отправку с обеих сторон. Завершение знакомства удаляет мэтч и историю рабочей базы. Уже отправленное в старом режиме бота остаётся в Telegram.

## Уведомления бота

Матчи и новые сообщения добавляют задачи в транзакционную таблицу `notifications`. Фоновый worker отправляет короткое уведомление и кнопку открытия нужного диалога в приложении.

Сетевые ошибки повторяются с задержкой, `retry_after` Telegram учитывается; максимум 10 попыток. Запрет отправки пользователю завершает задачу, но не удаляет сообщение в приложении. При блокировке/завершении знакомства задача не доставляется. Редкий дубль уведомления при аварии после отправки, но до фиксации результата, возможен; обещания exactly-once нет.

## Подключение к боту

Для реального запуска внутри Telegram нужен **публичный HTTPS-корень приложения**. Локальный адрес или только подготовленный Docker-образ не подключают Mini App к Telegram.

Новые переменные:

| Имя | Значение |
|---|---|
| `WEB_ENABLED=1` | Включить HTTP-сервер вместе с polling-процессом |
| `WEB_HOST` | По умолчанию `127.0.0.1`; в Docker `0.0.0.0` |
| `WEB_PORT` | По умолчанию `8080` |
| `WEBAPP_URL` | Реальный публичный HTTPS-корень, без query/fragment и подпути |
| `APP_DOMAIN` | Домен для Caddy, если используется Compose HTTPS-профиль |

Когда `WEBAPP_URL` задан, процесс сам устанавливает Telegram menu button «Открыть Мэтч», `/start` отдаёт кнопку приложения, и запускается worker уведомлений. Без URL текущий режим бота продолжает работать; вымышленный адрес к боту не привязывается.

Один Python-процесс обслуживает HTTP, polling, резервирование и уведомления с общим Store. Запрещён второй polling-процесс с тем же токеном; файловая блокировка защищает одну базу на одном хосте.

### Вариант сервера с собственным доменом

1. Нужен сервер с Docker и постоянным диском. Домен должен иметь DNS-запись на этот сервер, порты 80/443 доступны для Caddy.
2. Перенесите исходники и защищённо задайте `BOT_TOKEN`, `ADMIN_ID`, `APP_DOMAIN`, `WEBAPP_URL=https://<ваш-домен>` в окружении сервера либо приватном `.env` (исключён из Git и Docker-образа).
3. Остановите прежний polling. Согласованно перенесите существующую базу в named volume: Compose не импортирует локальную SQLite автоматически. Не удаляйте старую базу до проверки переноса.
4. `docker compose --profile https up -d --build` — Caddy получает и обновляет публичный сертификат, проксирует запросы в `bot:8080`.
5. Проверьте HTTPS, `/health`, `/start`, открытие меню приложения из Telegram и сценарий двумя аккаунтами. `/health` проверяет HTTP-процесс, а не доставку Telegram или состояние polling.

Прокси должен поддерживать SSE без буферизации и чтение долгих соединений. У Caddy это поддерживается. Отдельный сторонний хостинг в ходе разработки не был создан. Одной публикации конфигурации облачной среды недостаточно для публичного HTTPS-веб-сервиса.

## Локальные проверки

Дизайн без реальных данных: `python -m dating.webserver --port 8081`. Сервер слушает loopback и защищает API случайным временным ключом; в браузере работает исключительно демо. Не используйте этот сервер как production entry point.

```bash
python -m pip install --no-deps -e .
python -m pytest -q
# Дополнительно: настоящие браузерные тесты с системным Chromium
python -m pip install '.[ui]'
python -m pytest tests/test_web_ui.py -q
```

Браузерный тест создаёт двух подписанных тестовых Telegram-пользователей, проверяет настоящий API, мэтч, переписку в обе стороны, прочтение, темы, отсутствие горизонтального скролла и редактирование. Реальных Telegram-пользователей и токен в нём нет. Живой Telegram WebView и постоянный HTTPS-домен проверяются отдельно при публикации.

## Дополнительные таблицы

Схема v4 создаётся без удаления старых данных: `message_keys` (дедупликация), `message_reads` (прочтение), `notifications` (очередь), `deployment_state` (одноразовый первичный перенос). Удаление анкеты каскадно удаляет связанные записи. Автоматические резервные копии и ограничения SQLite описаны в README.

## Просмотр и редактирование без сервера

`python scripts/build_preview.py` создаёт `docs/metch-preview.html` и архив `docs/metch-preview.zip`. Откройте HTML обычным браузером: фотографии, стили и код встроены в один файл, Telegram SDK и сервер не используются. Только вымышленные анкеты и сообщения.

Кнопка **«Дизайн»** открывает редактор. Можно отдельно настроить обе темы (фон, поверхности, акцент и текст), скругление карточки и уменьшение анимации. Видна оценка контрастности текста. Изменения хранятся локально при доступном localStorage; если браузер запрещает его для файлов, экспорт JSON остаётся доступным. **«Сохранить дизайн в файл»** выгружает `metch-design.json` для передачи разработчику; импорт восстанавливает настройки. Изменения превью не меняют рабочую базу или опубликованный интерфейс.

Исходник редактора находится в `scripts/preview_editor.js`/`.css` и не входит в production Mini App. Большие HTML/ZIP-артефакты исключены из Git и Docker; их можно пересобрать. На этой облачной машине управляемый Chromium блокирует открытие `file://`; содержимое проверено как единый автономный документ с нулевыми внешними запросами, в том числе с непрозрачным origin. В обычном браузере открывается сам HTML-файл.

### Пакет для Windows

`python scripts/build_windows.py` собирает `docs/Metch-Windows.zip`. После «Извлечь всё» пользователь открывает `START.cmd`: он ищет Edge/Chrome в стандартных папках и открывает соседний автономный `metch-preview.html`. Если браузер не найден, используется стандартная ассоциация HTML. Все пути заключены в кавычки; delayed expansion отключён для имён папок с `!`. Никакие программы, серверы или ключи не устанавливаются. Запуск самого CMD в Windows на облачной Linux-машине не проверялся; содержимое превью и экспорт настроек проверены в Chromium, ZIP проверен по CRC и составу. Внутри архива есть инструкция и способ открыть HTML напрямую через Edge, без отключения защиты системы.
