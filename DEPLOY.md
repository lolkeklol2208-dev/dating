# Публикация Мэтч

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/lolkeklol2208-dev/dating)

Код запускается на Render как один Python web-service. Render предоставляет публичный HTTPS-адрес; покупать собственный домен не требуется. `render.yaml` запрашивает платный тариф Starter и постоянный диск 1 ГБ. Текущую стоимость и условия нужно проверить в Render перед созданием сервиса. Никакая оплата из облачной среды разработки не выполняется.

## Действия владельца

1. Открыть кнопку выше и войти в Render через GitHub. Разрешить доступ к репозиторию `lolkeklol2208-dev/dating`, если он приватный.
2. В поле `BOT_TOKEN` вставить токен **через защищённую форму Render**, а не в код, ссылку или Git. Ваш `ADMIN_ID` уже задан в конфигурации.
3. Проверить тариф/диск и подтвердить создание сервиса. Дождаться успешного deploy. Если импорт по кнопке не поддерживает приватный репозиторий, создать New → Blueprint и выбрать этот репозиторий.
4. Сообщить адрес сервиса разработчику для проверки и переноса текущей анкеты. Токен и пароль в чат повторно не отправлять.

## Что происходит автоматически

- Нативный Python runtime устанавливает зависимости по lock-файлу и приложение.
- `RENDER_EXTERNAL_URL` становится адресом Mini App, а `PORT` — портом HTTP-сервера. Ручное заполнение `WEBAPP_URL` не требуется.
- SQLite и последние семь ежедневных резервных копий находятся на `/var/data`, а не на временном диске сборки.
- Процесс регистрирует кнопку «Открыть Мэтч» в Telegram, отдаёт приложение на HTTPS-корне и запускает очередь уведомлений.
- `/admin` доступен только владельцу; все пользовательские API требуют подпись Telegram.
- Автоматические обновления с GitHub отключены, чтобы не менять работающий сервис без проверки.

## Переключение с текущей среды

Не оставлять два polling-процесса для одного токена. Во время первого запуска переключение согласуется с владельцем: сохранить согласованный SQLite backup, остановить старый процесс, запустить новый и проверить menu button и `/start`. Файловая блокировка защищает одну базу на одном сервере, но не два разных сервера.

В исходной базе на момент подготовки находилась одна анкета владельца, без мэтчей и переписки. Для этого случая подготовлен ограниченный перенос через подписанный API:

```bash
# BOT_TOKEN и ADMIN_ID уже должны быть безопасно заданы в окружении оператора.
python -m dating.backup --output /safe/path/pre-launch.sqlite3
python -m dating.migrate_profile --url https://ACTUAL-SERVICE.onrender.com --source /safe/path/pre-launch.sqlite3
```

Скрипт не перезаписывает другую версию анкеты на сервере. Он переносит фото, поля, фильтры и видимость и проверяет результат. Изображение повторно отправляется владельцу ботом для получения Telegram file ID. Исходная база не изменяется, старый черновик остаётся в резервной копии. Если появились другие пользователи, история, блокировки или жалобы, скрипт откажется: нужен полный перенос базы при остановленном процессе, а не подмена данными из демо.

Не удалять исходную базу и резервные копии до проверки. Проверить HTTPS, авторизацию, фото, мэтч и сообщения двумя реальными аккаунтами, уведомления, перезапуск и доступ к данным после него. Проверка `/health` подтверждает HTTP-ответ, но не весь пользовательский цикл.

## Границы проверенного

Конфигурация приложения, автоопределение Render URL/порта, подписи, охрана переноса и полный API/браузерный цикл проверены локально. Создание аккаунта, тарифа и диска Render, доступность выбранного Python runtime, применение blueprint провайдером и настоящий HTTPS deployment проверяются только после авторизации владельца. У агента нет привязанного аккаунта Render или API-ключа, поэтому наличие этого файла не означает, что сервис опубликован.
