# Мэтч · Telegram Mini App и бот уведомлений

Основной интерфейс теперь реализован как Telegram Mini App: **анкета → поиск → лайк → мэтч → встроенный мессенджер**. Две фиолетовые темы, анимированный логотип и пружинные свайпы. Бот служит для входа, уведомлений и модерации.

**Подключение, HTTPS, безопасность API, живой мессенджер и скриншоты: [MINIAPP.md](MINIAPP.md).** Пока `WEBAPP_URL` не задан, бот сохраняет прежний интерфейс, описанный ниже.

## Публикация

Основной вариант — Amvera: [AMVERA.md](AMVERA.md). Подготовлены Docker-сборка, постоянное хранилище и безопасный перенос базы. Фактический запуск требует аккаунта хостинга, защищённого ввода токена и подтверждения выбранного тарифа владельцем. Render оставлен только как альтернатива в [DEPLOY.md](DEPLOY.md).

## Пользовательский цикл

1. `/start`: объяснение правил, подтверждение 18+.
2. Семь шагов: имя, возраст, пол, предпочтения, город, описание, фото. Валидация каждого поля. Черновик сохраняется в SQLite между сообщениями и перезапусками.
3. Предпросмотр перед сохранением. Отмена оставляет существующую анкету без изменений.
4. Поиск учитывает город, пол и возрастные предпочтения **обоих** участников. Своя, скрытая, забаненная и заблокированная анкета исключается.
5. Пропуск или анонимный лайк. Повторное нажатие не меняет первоначальную реакцию и не создаёт дубликат мэтча. Можно вернуть только пропущенные анкеты.
6. Взаимный лайк создаёт мэтч и уведомляет обоих. Список мэтчей доступен даже при неудачной доставке уведомления.
7. «Написать» выбирает собеседника. Следующий текст до 2000 символов передаётся внутри бота. Никакой пересылки Telegram-профиля; содержимое экранируется. После мэтча также доступна ссылка на Telegram-профиль.
8. «Ответить» выбирает нужного человека, история показывает последние сообщения и позволяет листать назад. Получатель не обязан прямо сейчас находиться в этом диалоге.
9. «Выйти», переход в меню или команда снимают выбранного собеседника — следующий текст случайно ему не уйдёт.
10. Блокировка закрывает поиск и диалог в обе стороны. «Завершить знакомство» удаляет мэтч и историю в базе; старый лайк их не восстановит.
11. Анкету можно редактировать, скрыть или удалить. Удаление удаляет связанные реакции, диалоги, историю, жалобы и черновики. Сообщения в Telegram не отзываются.

## Запуск

Нужен Python 3.12+. Токен выдаёт **@BotFather → /newbot**. Никогда не добавляйте его в Git.

```bash
cd /workspace/dating # либо ваш путь к репозиторию
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
read -rsp 'Bot token: ' BOT_TOKEN; echo
export BOT_TOKEN
python -m dating
```

В подготовленной облачной среде: `source /workspace/.venvs/dating/bin/activate`. После установки также доступна команда `ryadom` (историческое имя CLI). Только **один** polling-процесс на токен. Файловая блокировка защищает от второго процесса на той же базе в Linux/macOS; не используйте разные базы для одного токена. Нативный запуск на Windows не поддерживается, используйте Docker/WSL. Публичный домен, webhook и входящие порты не нужны; требуется исходящий HTTPS к `api.telegram.org`.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный секрет BotFather |
| `DATABASE_PATH` | По умолчанию `data/dating.sqlite3` |
| `ADMIN_ID` | Telegram ID владельца для `/admin`; `/id` показывает собственный ID |
| `BACKUP_DIR` | По умолчанию `backups` рядом с БД; пустая строка отключает автоматические копии |
| `HTTPS_PROXY`, `NO_PROXY` | Стандартная настройка прокси |
| `SSL_CERT_FILE` | При необходимости доверенный CA-файл облачного прокси; проверка TLS остаётся включённой |

`.env.example` — справочник. Python самостоятельно `.env` не загружает. Используйте переменные среды или менеджер секретов сервера. Docker Compose умеет читать `.env`; этот файл исключён из Git и образа.

Команды: `/start`, `/app` (открыть Mini App), `/help`, `/cancel`, `/delete`, `/id`. Если Telegram скрывает кнопку меню, отправьте `/app`: бот пришлёт кнопку прямо в ответном сообщении. `/cancel` также выходит из выбранного диалога. `/start` начинает работу заново и отменяет текущий черновик; после обычного перезапуска процесса черновик сохраняется.

## Тестовые анкеты

В админ-панели доступен [каталог из 100 вымышленных анкет](docs/TESTING.md) девушек 20–30 лет: сгенерированные фото, разные описания, фильтры, оценки, заметки и CSV. Любой участник может открыть просмотр через «Знакомства → Посмотреть тестовые анкеты», в том числе со второго аккаунта без собственной анкеты. Оценки, заметки и CSV доступны только владельцу. Каталог отделён от реальных участников и не создаёт фиктивных мэтчей.

## Модерация

В Mini App доступна [админ-панель](docs/ADMIN.md): обзор, поиск людей, жалобы, бан/разбан с причиной и журнал решений. Кнопка со щитом видна только владельцу, даже без анкеты. `/admin` открывает её при настроенном `WEBAPP_URL`.

Задайте `ADMIN_ID`. Не назначайте первого пользователя администратором автоматически. Настроенный модератор должен открыть бота и нажать Start.

- `/admin`: статистика и кнопка панели; в режиме без Mini App — кнопка новых жалоб.
- Жалоба содержит причину и фото-карточку пользователя.
- «Забанить» требует отдельного подтверждения и закрывает доступ во всём боте.
- «Отклонить» закрывает жалобу; личная блокировка заявителя остаётся.
- `/unban ID`: снять глобальный бан.
- Любая административная команда и callback проверяют ID на сервере.
- Забаненный пользователь может удалить свою анкету, но минимальная запись бана (ID, причина, время) сохраняется, чтобы не допустить обхода через перерегистрацию.
- Если уведомление модератору не доставлено, жалоба остаётся в очереди `/admin`.

## База и резервные копии

SQLite: внешние ключи, WAL, индексы, сериализованные транзакции. Новые таблицы создаются при запуске без удаления существующих анкет. Таблицы: `profiles`, `reactions`, `matches`, `closed_matches`, `conversations`, `messages`, `blocks`, `reports`, `report_reviews`, `bans`, `fsm`, `moderation_audit` (а также таблицы Mini App).

Текст переписки хранится с отправителем, временем UTC и статусом доставки. `sent` означает принятие Telegram, **не прочтение**. При сетевой ошибке доставка может быть неопределённой: автоматического повтора нет во избежание дубликатов. История чужого диалога не доступна. История исчезает при удалении участника или завершении знакомства.

При запуске и каждые 24 часа создаётся согласованная онлайн-копия через SQLite backup API. Последние 7 автоматических копий сохраняются, остальные удаляются. Целостность копии проверяется; права файла — 0600. Ошибка копирования записывается в журнал, исходная БД не изменяется.

Ручная копия без остановки бота:

```bash
python -m dating.backup --output /safe/location/metch-backup.sqlite3
```

Существующий файл не перезаписывается. Автоматические копии на том же диске защищают от ошибок, но **не от потери сервера**. Для постоянной эксплуатации копируйте их в защищённое внешнее хранилище. Удалённые из рабочей базы данные могут оставаться в копиях до их ротации.

Восстановление: остановить бот, сохранить текущую БД и её `-wal`/`-shm` в отдельное место, поместить проверенную копию по `DATABASE_PATH`, убедиться в отсутствии старых WAL/SHM рядом с восстановленным файлом, запустить бот. Не заменяйте базу при работающем процессе.

## Контейнер и постоянный сервер

```bash
# BOT_TOKEN и ADMIN_ID задаются через защищённое окружение либо приватный .env.
docker compose up -d --build
docker compose logs --tail=50 bot
docker compose stop bot
```

Compose сохраняет SQLite и копии в named volume, запускает от непривилегированного пользователя с read-only корнем, перезапускает процесс после сбоев и ограничивает размер логов. **Не используйте `docker compose down -v`: это удалит данные.** Для переноса существующей БД сначала сделайте онлайн-копию и импортируйте её в volume при остановленном контейнере. Compose не импортирует базу из локальной папки автоматически.

Если Docker в облаке не имеет доступа к DNS/прокси, зависимости можно заранее скачать на основной машине, сохраняя стандартную проверку TLS:

```bash
python -m pip download --only-binary=:all: --dest wheelhouse -r requirements.lock setuptools==80.9.0 wheel==0.45.1
docker compose build
```

Dockerfile использует локальные колёса при наличии `wheelhouse`, иначе обычную установку из реестра. Секреты и база в образ не попадают. Сборка и автономная проверка контейнера не означают, что настроен внешний сервер или мониторинг. Нужны сервер с постоянным диском, внешние копии и наблюдение за журналами. Облачная сессия разработки не является обещанием хостинга 24/7.

## Проверки

```bash
python -m pip check
python -m pytest -q
```

Проверяется полный путь от заполнения и предпросмотра до мэтча, переписки, блокировки, модерации и удаления; сбой доставки, запрет чужой истории, старые кнопки, лимит частоты, сохранение формы/диалога после открытия БД заново, обновление схемы и резервное копирование живой WAL-базы.

Telegram в автоматических тестах заменён транспортом без сети. Ручная проверка двумя аккаунтами: совместимые анкеты в одном городе → встречные лайки → переписка в обе стороны → история → выход из диалога → блокировка/завершение → удаление → перезапуск. Настоящую доставку и внешний вид на разных клиентах Telegram следует проверять отдельно; тесты не заменяют проверку двумя людьми.

## Границы текущей версии

- Только текст в диалогах, одно фото в анкете. Нет видео, голосовых и оплат. Mini App реализован; открытие внутри Telegram требует публичного HTTPS-размещения.
- Город сравнивается по тексту без регистра с нормализацией «ё/е»; «СПб» и «Санкт-Петербург» — разные названия.
- Подтверждение возраста 18+ не проверяет документы. Автоматической проверки фотографий и массовых регистраций нет.
- Лимит частоты: 25 входящих действий за 10 секунд на пользователя в одном процессе, не защита от распределённого спама.
- Одна SQLite-база и один polling-процесс; для нескольких серверов нужны другая БД и координация.
- Нет очереди повторной доставки, отметок прочтения, сквозного шифрования и гарантий доставки при аварии между Telegram API и фиксацией статуса.
- Скрытие анкеты временно закрывает диалоги; включение возвращает доступ. Уже отправленное сообщение отозвать нельзя, в том числе при блокировке в момент отправки.
- Ссылка на Telegram-профиль может зависеть от настроек приватности пользователя.
- До массового публичного запуска нужны актуальные правила сервиса, контакт поддержки и процесс модерации.

Код: `bot.py` — анкеты и навигация, `features.py` — диалоги/модерация, `store.py` — данные и поиск, `storage.py` — черновики, `middleware.py` — доступ и лимиты, `backup.py`/`maintenance.py` — резервирование. Принципы интерфейса и сценарии — в [DESIGN.md](DESIGN.md).
