# Тестовые знакомства и ответы администратора

Этот режим позволяет другу пройти сценарий «анкета в основной ленте → лайк → тестовый мэтч → диалог», а владельцу — ответить через административную панель от имени вымышленного персонажа. Реальные Telegram-аккаунты для 100 персонажей не создаются.

## Для участника

1. Открыть Mini App через `/app` в боте и нажать «Включить тестовые знакомства» на экране знакомств.
2. Прочитать предупреждение, отметить пустую по умолчанию галочку и подтвердить участие. Уведомление прямо говорит, что персонажи вымышлены, мэтч моделируется, сообщения читает и пишет администратор, Telegram ID / имя / тестовая переписка сохраняются на сервере.
3. В основной ленте появятся виртуальные профили. При наличии подходящих реальных анкет они чередуются. Виртуальные персонажи берутся из набора 100 анкет 20–30 лет разных городов; это тестовый набор, не обещание настоящей взаимной симпатии и не результат подбора по реальным фильтрам.
4. Лайк создаёт отмеченный «Тестовый мэтч». Можно открыть чат, отправить текст до 2000 символов, получить ответ администратора, видеть историю и отметки прочтения. Пользовательская анкета для тестового сценария не обязательна.
5. Диалог доступен в общих разделах «Мэтчи» и «Диалоги», с подписью о виртуальном персонаже. В чате постоянно отображается пояснение о доступе администратора, ответы отмечены ролью «Администратор · от имени персонажа».
6. Можно завершить один диалог (мэтч и сообщения удалятся у обеих сторон) или выключить режим с удалением всех своих тестовых диалогов из рабочей базы. Реальные чаты сохраняются. Удаление своих данных через Mini App или `/delete` также удаляет тестовую сессию и все связанные записи.

После отключения согласие и сообщения больше не доступны API оператора. Уже прочитанное человеком нельзя отозвать; обычные резервные копии могут оставаться до ротации 7 копий. Для повторного включения требуется новое согласие.

## Для владельца

`/admin` → «Открыть админ-панель» → «Открыть тестовые диалоги» на вкладке «Обзор».

Список показывает участника, выбранного персонажа, последнее тестовое сообщение и непрочитанные. Владелец открывает нужную пару и отвечает от имени персонажа. В интерфейсе владельцу и участнику ясно показана роль администратора. Данные обычных личных диалогов не поступают в этот раздел.

Новые сообщения появляются через существующий SSE-канал с резервным обновлением примерно раз в 4 секунды. Тестовые мэтчи и сообщения не создают Telegram-уведомления и не попадают в счётчики реальных мэтчей / сообщений. Оператор и участник могут общаться, держа Mini App открытым.

## Хранение и проверки

SQLite v7 добавляет `virtual_sessions`, `virtual_reactions`, `virtual_threads`, `virtual_messages`. Согласие содержит версию и серверное время принятия. Все записи привязаны к подтверждённому Telegram ID участника; режим для другого пользователя администратор включить не может.

Операторские endpoints всегда проверяют `ADMIN_ID`. Участник имеет доступ только к собственным согласованным диалогам; роль отправителя и ID автора задаёт сервер, поля тела запроса не могут их заменить. `nonce` исключает повтор сообщения при повторной отправке. Переписка упорядочена, последние 40 сообщений загружаются с возможностью чтения более ранних. Отметка прочтения принимается только для сообщения этого диалога.

Бан скрывает тестовые диалоги из операторского списка и закрывает доставку. Отзыв согласия атомарно удаляет сессию, реакции, мэтчи и текст сообщений через внешние ключи. Постоянное хранилище и стандартные SQLite-копии включают этот режим. Новый импорт заполненной базы не допускается.

| Метод | Путь | Доступ |
|---|---|---|
| GET / POST | `/api/virtual/session` | Своя сессия; для включения нужны `enabled: true`, `accepted: true`, `version: 1` |
| POST | `/api/virtual/reactions` | Лайк / пропуск текущей виртуальной анкеты после согласия |
| GET | `/api/virtual/threads` | Свои тестовые мэтчи |
| GET / POST | `/api/virtual/threads/{id}/messages` | Своё чтение / отправка |
| POST | `/api/virtual/threads/{id}/read` | Своя отметка прочтения |
| DELETE | `/api/virtual/threads/{id}` | Завершить свой тестовый диалог |
| GET | `/api/admin/virtual/threads` | Только владелец; по 20 на страницу |
| GET / POST | `/api/admin/virtual/threads/{id}/messages` | Только владелец, только тестовая переписка |
| POST | `/api/admin/virtual/threads/{id}/read` | Отметка прочтения оператором |
