# Каталог для долгосрочного тестирования

Отдельный экран «100 тестовых анкет» удалён из Mini App, включая входы на главной и в админ-панели. Для проверки лайков и переписки используется основная лента: участник [включает тестовые знакомства](VIRTUAL.md), подтверждает согласие и видит персонажей среди анкет. Ответы владельца доступны через «Открыть тестовые диалоги» в админ-панели.

Подготовлено ровно 100 вымышленных анкет девушек 20–30 лет: разные имена, 10 городов, занятия, интересы, уникальные описания и 100 сгенерированных портретов. Персонажи не заимствованы с сайтов знакомств. Реалистичный вид не является заявлением о существовании этих людей. В основной ленте и диалогах сохраняются обозначения вымышленных персонажей и участия администратора.

Существующие API каталога сохраняют поиск, фильтры, административные оценки, заметки и экспорт в JSON. Отзывы хранятся в SQLite и входят в стандартные резервные копии; удаление экрана их не стирает. Статус / оценка / заметка изменяются только владельцем с проверкой ревизии: конфликт возвращает 409 и сохраняет предыдущую запись. Стабильные ID `test-001` … `test-100` отделены от Telegram ID. CSV-интерфейс удалён вместе с экраном.

## Данные и изоляция

- Базовый набор: `dating/web/test-profiles.json` (версия 1). Тексты и фото вымышлены; исходные данные содержат `is_test: true`.
- Портреты: 10 сгенерированных изображений `dating/web/images/test-portraits-01.png` … `test-portraits-10.png`. Каждое содержит сетку 5 × 2. Карточка показывает свою отдельную ячейку средствами CSS. Так браузер не скачивает отдельный большой файл для каждой карточки. Один портрет соответствует одной паре «изображение + ячейка»; всего 100 пар.
- Заметки: отдельная таблица SQLite `test_profile_reviews`. Схема v6 добавляет её без изменения существующих данных. Обычные резервные копии SQLite включают заметки. Это не отдельная внешняя резервная копия.
- API чтения и записи заметок доступен только настроенному `ADMIN_ID` после проверки подписанных Telegram initData. Отдельный API просмотра `/api/test-profiles` доступен обычному авторизованному участнику и читает только неизменяемые вымышленные данные, не обращаясь к таблице оценок. Он не возвращает `review`, заметки, оценки или сводку проверок. Публичные статические файлы содержат только вымышленные тексты/изображения, без заметок администратора.
- Сам просмотр набора не добавляет Telegram-аккаунты в `profiles`, не создаёт мэтчи или уведомления. [Тестовые знакомства](VIRTUAL.md) отдельно включаются самим участником после согласия: тогда персонажи появляются в основной ленте, а в явно обозначенных тестовых диалогах отвечает администратор. Тестовые ID не принимаются API реальных реакций/диалогов.
- Число тестовых карточек и статус их проверки доступны в административном API отдельно от статистики реальных анкет. Оценки описывают проверку каталога, а не востребованность сервиса или поведение настоящей аудитории.

## API

Все пути требуют `X-Telegram-Init-Data`. Пути `/api/admin/…` дополнительно требуют административную роль; обычный просмотр доступен всем участникам.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/test-profiles` | Просмотр: q, city, min_age, max_age, offset; без данных проверок |
| GET | `/api/test-profiles/{id}` | Вымышленная карточка без оценок и заметок; запись недоступна |
| GET | `/api/admin/test-profiles` | q, city, min_age, max_age, status, offset; 20 на страницу |
| GET | `/api/admin/test-profiles/export` | Все 100 с оценками и заметками в JSON |
| GET | `/api/admin/test-profiles/{id}` | Карточка и текущая ревизия заметки |
| POST | `/api/admin/test-profiles/{id}` | rating (0–5), status (new/reviewed/needs_work), notes, revision |

Каталог подходит для проверки отображения, фильтров, навигации и организации ручного QA. Проверка настоящих взаимных лайков, сообщений, доставки уведомлений и поведения аудитории требует отдельных тестовых аккаунтов с согласившимися участниками; синтетические данные не подменяют эти измерения.
