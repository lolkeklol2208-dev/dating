# Каталог для долгосрочного тестирования

Владелец открывает `/admin` в боте → «Открыть админ-панель» → «Открыть тестовый каталог» на вкладке «Обзор». Анкета администратора для этого не нужна.

Подготовлено ровно 100 вымышленных анкет девушек 20–30 лет: разные имена, 10 городов, занятия, интересы, уникальные описания и 100 сгенерированных портретов. Персонажи не заимствованы с сайтов знакомств. Реалистичный вид не является заявлением о существовании этих людей. Общая надпись и каждая карточка явно обозначают тестовые данные.

Каталог позволяет:

- Смотреть карточки по 20 на страницу, открывать полный текст и фото.
- Искать по имени, занятию, описанию и интересам, выбирать город и диапазон возраста.
- Ставить оценку 1–5 или оставлять без оценки; сохранять статус «Не проверена», «Проверена», «Доработать» и заметку до 2000 символов.
- Вернуться позже к сохранённой оценке или заметке, фильтровать по статусу.
- Выгрузить все 100 анкет вместе с оценками в CSV (UTF-8 с BOM, разделитель `;`). Значения, похожие на формулы, экранируются для таблиц. Скачивание из Telegram зависит от поддержки файлов клиентом; каталог и заметки работают без скачивания.

При конфликте двух открытых окон сервер возвращает 409 и сохраняет ранее записанную заметку. Обновление набора не стирает отзывы: стабильные ID `test-001` … `test-100` отделены от Telegram ID.

## Данные и изоляция

- Базовый набор: `dating/web/test-profiles.json` (версия 1). Тексты и фото вымышлены; исходные данные содержат `is_test: true`.
- Портреты: 10 сгенерированных изображений `dating/web/images/test-portraits-01.png` … `test-portraits-10.png`. Каждое содержит сетку 5 × 2. Карточка показывает свою отдельную ячейку средствами CSS. Так браузер не скачивает отдельный большой файл для каждой карточки. Один портрет соответствует одной паре «изображение + ячейка»; всего 100 пар.
- Заметки: отдельная таблица SQLite `test_profile_reviews`. Схема v6 добавляет её без изменения существующих данных. Обычные резервные копии SQLite включают заметки. Это не отдельная внешняя резервная копия.
- API чтения и записи заметок доступен только настроенному `ADMIN_ID` после проверки подписанных Telegram initData. Публичные статические файлы содержат только вымышленные тексты/изображения, без заметок администратора.
- Набор не добавляет Telegram-аккаунты в `profiles`, не попадает в поиск реальных участников, не создаёт мэтчи или уведомления, не открывает переписку от имени персонажей. Тестовые ID не принимаются API реальных реакций/диалогов.
- Число тестовых карточек и статус их проверки показываются отдельно от статистики реальных анкет. Оценки описывают проверку каталога, а не востребованность сервиса или поведение настоящей аудитории.

## API

Все пути требуют `X-Telegram-Init-Data` и административную роль.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/admin/test-profiles` | q, city, min_age, max_age, status, offset; 20 на страницу |
| GET | `/api/admin/test-profiles/export` | Все 100 с оценками и заметками в JSON |
| GET | `/api/admin/test-profiles/{id}` | Карточка и текущая ревизия заметки |
| POST | `/api/admin/test-profiles/{id}` | rating (0–5), status (new/reviewed/needs_work), notes, revision |

Каталог подходит для проверки отображения, фильтров, навигации и организации ручного QA. Проверка настоящих взаимных лайков, сообщений, доставки уведомлений и поведения аудитории требует отдельных тестовых аккаунтов с согласившимися участниками; синтетические данные не подменяют эти измерения.
