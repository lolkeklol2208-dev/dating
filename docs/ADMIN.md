# Администрирование Мэтч

В Mini App администратор видит кнопку со щитом в верхней панели. Команда `/admin` в боте также открывает панель. Создавать анкету для администрирования не требуется.

Доступ определяется только сервером: подписанные Telegram `initData` и точное совпадение с `ADMIN_ID`. Для этого проекта владелец — `8815384274`. Клиент не назначает роли. Обычные участники получают 403 на каждом административном endpoint; без подписанной сессии — 401.

На вкладке «Обзор» также доступен [тестовый каталог](TESTING.md) из 100 вымышленных анкет с оценками и заметками. Он не изменяет статистику реальных участников.

## Базовые возможности

- **Обзор:** число анкет, анкет в поиске, мэтчей, сообщений, новых жалоб и банов. Это текущие счётчики, не число людей онлайн или активность за день.
- **Люди:** поиск по имени, username, городу и точному Telegram ID, фильтры статуса, страницы по 20 записей. Здесь анкеты и отдельные баны; незавершённые черновики не являются анкетами.
- **Карточка:** фото, поля анкеты, ID, username, число мэтчей и полученных жалоб, причина блокировки. Содержимое личной переписки в панели не открывается.
- **Жалобы:** очередь и обработанные жалобы, причина, заявитель, просмотр текущей анкеты. Решение: заблокировать или отклонить. Панель не сохраняет отдельную копию удалённой анкеты/переписки как доказательство.
- **Бан / разбан:** требуется причина и подтверждение. Бан закрывает поиск и диалоги, сохраняется после удаления анкеты. Нельзя заблокировать собственный административный аккаунт. Разбан не отменяет личные блокировки участников.
- **Журнал:** кто, когда, кого и по какой причине заблокировал / разблокировал или отклонил жалобу. Минимальная запись с ID и решением сохраняется отдельно от анкеты. Старые решения до появления журнала не получают выдуманных дат и причин.

Решение по жалобе, изменение бана и запись журнала выполняются одной транзакцией. Повторное решение по закрытой жалобе возвращает 409. Защита работает и при одновременных запросах. Старые кнопки модерации в боте используют ту же транзакцию.

## API

Все запросы используют `X-Telegram-Init-Data` и общую защиту / ограничения API.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/admin/overview` | Счётчики |
| GET | `/api/admin/users?q=&status=all&offset=0` | Поиск, статусы all/visible/hidden/banned |
| GET | `/api/admin/users/{id}` | Карточка |
| GET | `/api/admin/reports?status=open&offset=0` | open/reviewed |
| GET | `/api/admin/audit?offset=0` | Журнал |
| POST | `/api/admin/moderate` | target, action (ban/unban/dismiss), reason; report_actor для решения по жалобе |

Схема SQLite v5 добавляет только таблицу `moderation_audit`. Обновление сохраняет существующие анкеты, мэтчи, диалоги и баны. Полный повторный импорт базы для обновления не нужен и запрещён на заполненном сервере.

## Что ещё нужно перед широким запуском

1. Проверить на реальном телефоне владельца открытие Mini App и админки, затем двумя Telegram-аккаунтами пройти регистрацию → взаимный лайк → переписку → уведомления → жалобу → решение.
2. Организовать отдельную резервную копию вне Amvera и проверить восстановление на изолированной базе. Автоматические 7 копий на том же постоянном диске не защищают от потери самого диска или аккаунта.
3. Настроить внешнюю проверку доступности `/health`, оповещения об остановке и достаточном балансе хостинга. Подключение платного сервиса или отправка внешних оповещений — отдельная настройка владельца.
4. Указать реальные контакты поддержки, владельца сервиса и согласовать правила/политику обработки данных для публичного запуска. Не выдумывать юридические реквизиты.
5. До роста аудитории добавить защиту от массовой регистрации и спама. Текущая проверка 18+ основана на введённом пользователем возрасте; она не является проверкой документов. Фото и сообщения сейчас проверяются по жалобам вручную.

Несколько модераторов с ролями, доказательства по жалобам, апелляции, рассылки и расширенная аналитика — следующие функции, базовая версия их не обещает.
